## 1. 全体の構成

```
ブラウザ（templates/index.html + static/app.js）
   │  HTTP（JSON / multipart）     ※ 127.0.0.1 のみ。他サイトからの操作は断る
   ▼
Flask（app.py）… API の受け口。入力の検査とエラーの日本語化だけを担当し、処理は services/ に任せる
   │
   ├─ services/pdf_renderer   PDFの検査と画像化（PyMuPDF）
   ├─ services/ocr_engine     EasyOCR（1回だけ読み込み、排他制御）
   ├─ services/ocr_pipeline   1ページ分の読み取りの流れ（下記 3章）
   │     ├─ table_lines       罫線の検出
   │     ├─ table_mapper      行×項目への割り当て
   │     ├─ ocr_refine        欄ごとの読み直し
   │     ├─ candidates        マスタの値での補正
   │     └─ header_extract    見出し項目の抽出
   ├─ services/review         OCRと正解の比較・判定・集計
   ├─ services/returns        マスタ・売上との照合とチェック（slip_check と組）
   ├─ services/master_import  Excel/CSV → SQLite の取り込み
   ├─ services/excel_export   基幹システム取込用Excel
   ├─ services/doc_store      伝票ごとの記録フォルダ（records/）
   └─ services/db             SQLite の接続と表の作成
```

設計の方針（要件定義書 2章）をコードでどう守っているか：

| 方針 | 実現のしかた |
|---|---|
| データを外に出さない | OCR・DB・ファイルはすべてPC内。`HOST = 127.0.0.1`。Origin/Referer を見て他サイトからの操作を断る（app.py `block_foreign_requests`） |
| 推測で埋めない | 割り当ては位置だけ（table_mapper）。読み直しは「文字種を絞って読む」だけで、内容から値を作らない（ocr_refine）。マスタでの補正は「1つに決まるときだけ」（candidates） |
| 迷ったら人に任せる | 自信の低い欄は黄色、候補が複数なら人が選ぶ、エラーがあれば確定できない |
| 記録を壊さない | 記録はPDFの内容（SHA-256）ごとのフォルダ。書き込みは一時ファイル経由。確定済み・出力済みは一覧から外せない |

## 2. 画面

1つのHTML（`templates/index.html`）で、左のレールと右の作業領域からなる。画面の切り替えは JavaScript（`static/app.js`）が行う。

| 画面 | 要件 | 主な要素 | 操作 |
|---|---|---|---|
| **読み込み** | F1 | ドラッグ＆ドロップ領域、「ファイルを選択」 | PDFを置くとすぐ読み込み、未OCRのものは自動でOCR |
| **伝票一覧** | F2 | 状態の絞り込み（すべて／要確認／エラー／問題なし／確定済み／出力済み）、伝票の表（ファイル・状態・会社・伝票番号・計上月・あと何か所／何件・合計）、出力先フォルダ | 「開く」で作業画面へ。「未OCRをまとめてOCR」「問題なしの伝票をまとめて確定」「確定済みを取込用Excelに出力」 |
| **作業画面** | F3・F4・F6・F7・F9 | 左：伝票の画像（枠を重ねて表示、拡大縮小）。右：伝票情報（会社名・会社コード・伝票番号・返品日・元売上番号、OCRの自信度つき）、明細の表（行・区分・品番・枝番・数量・単価・返品理由・良品/不良／税率・元の売上）、合計と照合（エラー・警告・マスタの会社・税率ごとの合計） | 入力欄を書き換えると自動保存して照合し直す。黄色の欄が「人が確認する欄」。「この伝票を確定」「確定を取り消す」 |
| **マスタ・売上データ** | F8 | 取引先・商品・返品理由・売上の4種類。件数、見本Excelのダウンロード、ファイル選択、「取り込む」 | 1行でもエラーがあれば取り込まず、行・列・理由の一覧を表示 |
| **精度の記録** | 非機能 | 枠の割り当てと正解の記録、ページ別・項目別の正解率 | 折りたたみ。正解を入力するとOCRと比べて判定（一致／表記差／不一致） |

画面の状態（伝票一覧の「状態」列）：

| 状態 | 意味 | 決め方 |
|---|---|---|
| 未OCR | 読み込んだだけ | OCR結果のページが無い |
| 要確認 | 人が確認する欄が残っている | 自信の低い欄、または必須の欄が空 |
| エラー | 入力チェック（F4）か照合（F9）でエラー | returns.check の errors が1件以上 |
| 問題なし | 確定できる | errors が0件（警告はあってもよい） |
| 確定済み | 確定した（返品記録に登録済み） | doc.json の state |
| 出力済み | 取込用Excelに出した | doc.json の state。取り消せない |

## 3. 処理の流れ

### 3.1 読み込みから確定まで

```
PDF ─(F1)─▶ 検査・画像化 ─▶ OCR ─▶ 割り当て ─▶ 読み直し ─▶ マスタで補正 ─▶ 見出し抽出
                                                                      │
          records/<伝票>/ocr/page_NN.json に保存 ◀───────────────────┘
                                                                      │
人が入力（自動保存）─▶ review.json ─▶ 照合・チェック（F4・F9）─▶ エラー0件なら確定（F7）─▶ t_return_slip / t_return_line に登録
```

### 3.2 1ページの読み取り（services/ocr_pipeline.read_page）

| 順 | 処理 | 部品 | 失敗したとき |
|---|---|---|---|
| 1 | ページ全体をOCRし、文字枠（文字・位置・自信度）のリストにする | ocr_engine.run_ocr | 例外は AppError にして画面に原因と対処を出す |
| 2 | 画像から縦の罫線を見つける | table_lines.vertical_lines | 見つからなければ空（見出しの中間で区切る） |
| 3 | 見出し（品番・枝番・数量・単価・返品理由）を探し、列の範囲と行の帯を決め、文字枠を行×項目に割り当てる。読み違えた見出しは並び順から推定 | table_mapper.propose_rows | 見出しが揃わなければ割り当てない（人が枠を選ぶ） |
| 4 | 見出し項目の値（会社コード・伝票番号・返品日・元売上番号）を、文字種を絞って読み直す | ocr_refine.refine_header | 読めなければ元の値のまま |
| 5 | 明細の欄（品番・枝番・数量・単価）を切り出し、拡大し、文字種を絞って読み直す。割り当てが無かった欄は列×行の範囲を読み、自信が高ければ新しい枠として追加。空欄は読まない | ocr_refine.refine_cells | 読めなければ元の値のまま |
| 6 | 品番・返品理由・元売上番号を、マスタ・売上データの値で補正（1つに決まるときだけ） | candidates.apply_known | 決まらなければ触らない |
| 7 | 見出し項目を抽出して返す | header_extract | 見つからなければ空（人が入力） |

効果は `tools/ocr_benchmark.py` で測る（要件定義書 F3.1：54.2% → 97.4%）。

### 3.3 出す値の決め方（F6）と照合（F9）

- 各欄の値は「人が入力した正解 → 採用したOCRの値」の順で決める（slip_check.cell_value）。OCRの値は最初から採用し、要確認の欄だけ採用しない
- 照合は returns.check が1枚単位で行う。会社（コード→別名→名前）、元の売上（番号→候補）、品番、返品できる残り、単価、返品理由、良品/不良、値引の税率、計上月（締め日）の順にエラー・警告を積む
- マスタ・売上は照合に使うだけで、伝票の値を上書きしない

### 3.4 取込用Excelの出力（F5）

一覧の「確定済みを取込用Excelに出力」→ `/api/export` → excel_export が `import_format.json` の列定義どおりに1ファイルにまとめる → 出力履歴（export_history.csv）に追記 → 伝票を「出力済み」にする。同じ伝票を2回出すと警告。出力先は設定（settings.json）で変えられ、無ければ作る。

**未実装（Issue #24）**：[返品計上Excel定義書](返品計上Excel定義書.md) の返品計上Excel。値引の按分（税率ごとの金額の比率で分ける計算。returns.py にあり、作業画面の「合計と照合」に表示）を、税率ごとの2行に分けて出す部分がまだ無い。

## 4. API 一覧（app.py）

すべて JSON を返す。失敗は `{"ok": false, "error": 原因, "hint": 対処, "code": 種別}`。

| メソッド・URL | 要件 | 入力 | 出力 |
|---|---|---|---|
| GET `/` | - | - | 画面（HTML） |
| POST `/api/docs/batch` | F1 | multipart `pdfs[]`（最大20、各20MB） | ファイルごとの成否、伝票一覧 |
| POST `/api/docs` | F1 | multipart `pdf` | 伝票1件 |
| GET `/api/docs` | F2 | - | 伝票一覧（状態・会社・伝票番号・計上月・残り・合計） |
| GET `/api/docs/<id>` | F2 | - | 伝票の詳細 |
| DELETE `/api/docs/<id>` | F2 | - | 一覧から外す（確認中のみ） |
| GET `/api/docs/<id>/pages/<n>` | F3 | - | ページ画像（PNG, base64）・OCR結果・割り当て・正解 |
| POST `/api/docs/<id>/pages/<n>/ocr` | F3 | - | OCR結果（文字枠・割り当て・見出し候補）。DBのマスタ値を補正に使う |
| PUT `/api/docs/<id>/pages/<n>/review` | F3・F6 | 行ごとの割り当て・正解・区分・良品不良・税率・元の売上 | 判定結果・集計 |
| GET / PUT `/api/docs/<id>/header` | F3 | 見出し項目の値 | 保存結果 |
| GET `/api/docs/<id>/check` | F4・F9 | - | エラー・警告・マスタの会社・候補・税率ごとの合計 |
| POST `/api/docs/<id>/confirm` | F7 | - | 確定（エラーがあれば400） |
| DELETE `/api/docs/<id>/confirm` | F7 | - | 取り消し（出力済みは400） |
| POST `/api/docs/confirm-all` | F7 | - | 問題なしの伝票をまとめて確定 |
| POST `/api/export` | F5 | - | 出力したファイル名・件数・除いた伝票と理由 |
| GET / PUT `/api/settings` | F5 | 出力先フォルダ | 設定（無いフォルダは作ってお知らせ） |
| GET `/api/import/kinds` | F8 | - | 取り込める種類・列名・今の件数 |
| GET `/api/import/<kind>/template` | F8 | - | 見本Excel |
| POST `/api/import/<kind>` | F8 | multipart `file`（xlsx/csv） | 取り込んだ件数、またはエラー行の一覧（400） |

## 5. 保存するもの

| 場所 | 何を | 形式 | 備考 |
|---|---|---|---|
| `records/<伝票名_ハッシュ>/original.pdf` | PDF本体 | PDF | 再起動しても一覧に戻る |
| `records/<伝票名_ハッシュ>/doc.json` | 伝票の状態・見出し項目・確定日時 | JSON | state: 確認中／確定済み／出力済み |
| `records/<伝票名_ハッシュ>/ocr/page_NN.json` | OCR結果（文字枠・割り当て・見出し候補） | JSON | 読み直し・補正した枠には refined / matched の印 |
| `records/<伝票名_ハッシュ>/review.json` | 人の入力（正解・区分・良品不良・税率・元の売上） | JSON | 自動保存 |
| `records/<伝票名_ハッシュ>/review_cells.csv`, `summary.csv` | 判定の明細と集計 | CSV | 精度の記録用 |
| `records/returns.db` | マスタ・売上・返品記録 | SQLite | 表は [データ設計書](データ設計書.md) |
| `records/settings.json` | 出力先フォルダ | JSON | |
| `records/export_history.csv` | 出力履歴 | CSV | 重複出力の警告に使う |
| `import_format.json` | 取込用Excelの列定義 | JSON | コードを変えずに列を変えられる |

## 6. 設定値（config.py）

| 名前 | 意味 | 初期値 |
|---|---|---|
| HOST / PORT | 待ち受け | 127.0.0.1 / 5000 |
| MAX_UPLOAD_MB | PDF 1ファイルの上限 | 20 |
| RENDER_DPI | PDFを画像にする解像度 | 200 |
| LOW_CONFIDENCE | これ未満の自信度は「要確認」 | 0.5 |
| TABLE_HEADERS / REVIEW_FIELDS | 明細の見出しと確認する項目 | 品番・枝番・数量・単価・返品理由 |
| USE_TABLE_LINES | 罫線で列を決める | True |
| REFINE_CELLS / REFINE_ALLOWLIST | 欄の読み直しと、列ごとの文字種 | True / 数量は数字だけ 等 |
| REFINE_MIN_CONF_NEW / REFINE_MIN_INK | 新しい枠として採用する自信度／空欄とみなす黒の割合 | 0.6 / 0.004 |
| USE_KNOWN_VALUES | マスタの値で補正する | True |

## 7. 人が判断する点（設計上、あえて自動にしていないところ）

- 良品／不良、値引の税率、元の売上の候補が複数あるときの選択
- OCRの自信が低い欄の採用（黄色の欄）
- マスタの補正で「1つに決まらない」値（例：FILE-0551 と FILE-0552 の1文字違い）
- 締め日を過ぎた伝票を次月に計上してよいか（警告を出すだけで確定はできる）
