# 要件定義書：複数PDFの読み込みと販売管理システム取込用Excelの出力

| 項目 | 内容 |
|---|---|
| 対象 | 返品伝票OCR（return_slip_ocr） |
| 版 | 1.0 |
| 関連 | Issue #1 |

## 1. 背景と目的

### 1.1 現状の業務
事務担当者は、取引先から届いた返品伝票（PDF）を1枚ずつ目で見て、販売管理システムに手入力している。

1. 返品伝票を受け取る
2. 品番・枝番・数量・単価・金額を目視で確認する
3. 販売管理システムに返品として手入力する（売上のマイナス計上・在庫戻し）

### 1.2 課題
- 伝票の枚数が多いと、入力に時間がかかる
- 手入力のため、打ち間違いが起きる。金額を間違えると請求額までずれる
- 現在のアプリは「PDFを1つずつ読み、精度を記録する」ところまでで、システムへの取込データは作れない

### 1.3 目的
複数の返品伝票PDFをまとめて読み取り、人が確認した結果を **販売管理システムにそのまま取り込めるExcel** として出力する。
これにより、手入力の時間と打ち間違いを減らす。

## 2. 方針

| 方針 | 理由 |
|---|---|
| **人の確認を必ず通す** | OCRは間違えることがある。確認していないデータはシステムに取り込ませない |
| **取込フォーマットは設定ファイルで決める** | 取込先のシステムや書式が変わっても、コードを書き換えずに対応できるようにする |
| **1件の失敗で全体を止めない** | 複数PDFのうち1つが壊れていても、ほかのPDFは処理を続ける |
| **データを外に出さない** | 現行どおり、OCRはPC内だけで実行する |

## 3. 機能要件

### F1. 複数PDFの一括アップロード
- 複数のPDFを一度に選択（またはドラッグ＆ドロップ）できる
- 1回のアップロード上限：20ファイル、1ファイル20MBまで
- 読み込めないPDF（破損・暗号化・PDF以外）は **そのファイルだけエラー** として一覧に表示し、ほかは続ける

### F2. 伝票一覧
- アップロードしたPDFを一覧で表示する
- 各伝票の状態を表示する：`未OCR` / `確認中` / `確認済み` / `エラー`
- 一覧から伝票を選ぶと、現在の確認画面（明細の割り当て・正解入力）を開く

### F3. 伝票ヘッダ項目の読み取り
明細に加えて、取込に必要な次の項目を読み取り、確認できるようにする。

| 項目 | 読み取り方 |
|---|---|
| 伝票番号 | 「伝票番号」「伝票No」などの見出しの右または下の文字 |
| 返品日 | 「返品日」「日付」などの見出しの右または下の文字。日付として解釈できる形式にそろえる |
| 取引先名 | 「取引先」「御中」などの位置から読み取る |

- 読み取れなかった項目は空欄にし、人が入力する（推測で埋めない）

### F4. 入力チェック
Excel出力の前に、次をチェックする。エラーがある伝票は出力しない。

| No | チェック内容 | 種類 |
|---|---|---|
| C1 | 必須項目（伝票番号・返品日・取引先・品番・数量・単価・金額）が入っている | エラー |
| C2 | 数量・単価・金額が数値である | エラー |
| C3 | 数量 × 単価 ＝ 金額 になっている | エラー |
| C4 | 返品日が日付として正しい | エラー |
| C5 | 取引先名が取引先マスタに登録されている（コードに変換できる） | エラー |
| C6 | 同じ伝票番号が、出力済みのデータにすでにある | 警告（出力は可能） |

### F5. 取込用Excelの出力
- 状態が `確認済み` で、チェックエラーがない伝票をまとめて **1つのExcelファイル** に出力する
- 列の並び・列名・形式は「取込フォーマット定義書」に従う
- 出力時に、出力しなかった伝票とその理由を画面に表示する
- 出力ファイル名：`返品取込_YYYYMMDD_HHMMSS.xlsx`

### F6. 出力値の決め方
| 状態 | Excelに出す値 |
|---|---|
| 人が正解を入力している | 正解の値（表記ゆれをそろえたもの） |
| 正解が未入力で、OCR結果を「このままでOK」と確定した | OCRの値（表記ゆれをそろえたもの） |
| どちらでもない | 出力しない（その伝票は `確認中` のまま） |

## 4. 非機能要件

| 項目 | 内容 |
|---|---|
| 性能 | 20ファイル（各1〜2ページ）を、一般的なノートPCで処理できること。OCR中も画面は操作できること |
| 信頼性 | 処理途中でアプリを閉じても、確認済みの記録は失われないこと（現行どおり） |
| セキュリティ | PDFと記録はPC内にのみ保存し、外部に送信しないこと |
| 保守性 | 取込フォーマットと取引先マスタは、設定ファイルの変更だけで変えられること |
| テスト | チェック処理（F4）とExcel出力（F5）は、自動テスト（pytest）で確認できること |

## 5. 対象外（今回はやらない）
- 販売管理システムへの直接の登録（APIなど）。今回はExcel出力まで
- 手書き伝票の読み取り
- 複数人での同時利用
