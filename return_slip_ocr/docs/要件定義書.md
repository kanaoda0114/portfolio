## 1. 背景と目的

### 1.1 現状の業務
事務担当者は、取引先から届いた返品伝票（PDF）を1枚ずつ目で見て、販売管理システムに手入力している。

1. 返品伝票を受け取る
2. 品番・枝番・数量・単価・金額・**返品理由**を目視で確認する
3. 返品理由と現物の状態から、**良品（在庫に戻す）か不良品（廃棄・メーカー返品）か**を判断する
4. 販売管理システムに返品として手入力する（売上のマイナス計上・在庫戻し）

### 1.2 課題
- 伝票の枚数が多いと、入力に時間がかかる
- 手入力のため、打ち間違いが起きる。金額を間違えると請求額までずれる
- 現在のアプリは「PDFを1つずつ読み、精度を記録する」ところまでで、システムへの取込データは作れない

### 1.3 目的
複数の返品伝票PDFをまとめて読み取り、人が確認した結果を **販売管理システムにそのまま取り込めるExcel** として出力する。
これにより、手入力の時間と打ち間違いを減らす。

## 2. 方針

| 方針 | 理由 |
|---|---|
| **人の確認を必ず通す** | OCRは間違えることがある。人が確定していないデータはシステムに取り込ませない |
| **推測で埋めない** | 読めなかった項目や、判断が必要な項目（良品/不良など）は人が入力する |
| **取込フォーマットは設定ファイルで決める** | 取込先のシステムや書式が変わっても、コードを書き換えずに対応できるようにする |
| **1件の失敗で全体を止めない** | 複数PDFのうち1つが壊れていても、ほかのPDFは処理を続ける |
| **データを外に出さない** | 現行どおり、OCRはPC内だけで実行する |

## 3. 機能要件

### F1. 複数PDFの一括アップロード
- 複数のPDFを一度に選択（またはドラッグ＆ドロップ）できる
- 1回のアップロード上限：20ファイル、1ファイル20MBまで
- 読み込めないPDF（破損・暗号化・PDF以外）は **そのファイルだけエラー** として一覧に表示し、ほかは続ける

### F2. 伝票一覧
- アップロードしたPDFを一覧で表示する
- 各伝票の状態を表示する：`未OCR` / `確認中` / `確定済み` / `出力済み` / `エラー`
- 一覧から伝票を選ぶと、確認画面（明細の割り当て・正解入力）を開く

### F3. 伝票ヘッダ項目・返品理由の読み取り
明細に加えて、取込に必要な次の項目を読み取り、確認できるようにする。

| 項目 | 単位 | 読み取り方 |
|---|---|---|
| 伝票番号 | 伝票 | 「伝票番号」「伝票No」などの見出しの右または下の文字 |
| 返品日 | 伝票 | 「返品日」「日付」などの見出しの右または下の文字。日付として解釈できる形式にそろえる |
| 取引先名 | 伝票 | 「取引先」「御中」などの位置から読み取る |
| 返品理由 | 明細 | 明細表の「返品理由」「理由」列から読み取る。伝票全体に1つだけ書かれている場合は、全明細に同じ値を使う |
| 良品/不良区分 | 明細 | **読み取らず、人が選ぶ**（`良品` / `不良`）。返品理由から推測しない |

- 読み取れなかった項目は空欄にし、人が入力する

### F4. 入力チェック
確定（F7）とExcel出力（F5）の前に、次をチェックする。

| No | チェック内容 | 種類 |
|---|---|---|
| C1 | 必須項目（伝票番号・返品日・取引先・品番・数量・単価・金額・良品/不良区分）が入っている | エラー |
| C2 | 数量・単価・金額が数値である | エラー |
| C3 | 通常の明細で、数量 × 単価 と 金額 の差が許容差（初期値：1円）以内である。値引き行は対象外 | **警告**（確定・出力は可能） |
| C4 | 返品日が日付として正しい | エラー |
| C5 | 取引先名が取引先マスタに登録されている（コードに変換できる） | エラー |
| C6 | 同じ「取引先コード＋伝票番号」が、出力履歴にすでにある | 警告（出力は可能） |

**C3 の補足**
- **値引き行**：品番が空欄で、品名や金額欄に「値引」「割引」とある行、または金額がマイナスの行。明細区分を `値引` とし、数量×単価のチェックはしない
- **端数**：単価に小数がある場合、数量×単価の端数で1円以内のずれが出ることがある。端数の処理方法（四捨五入・切り捨てなど）は取込先の仕様によるため、7章で確認する。確認できるまでは警告にとどめ、人が判断する
- 許容差は設定ファイルで変更できる

### F5. 取込用Excelの出力
- 状態が `確定済み` で、チェックエラー（C1・C2・C4・C5）がない伝票をまとめて **1つのExcelファイル** に出力する
- 列の並び・列名・形式は「取込フォーマット定義書」に従う
- 出力時に、出力しなかった伝票とその理由、警告（C3・C6）がある伝票を画面に表示する
- 出力ファイル名：`返品取込_YYYYMMDD_HHMMSS.xlsx`
- 出力先：**利用者がツールの画面で設定する**（フォルダのパスを入力して保存）。設定した出力先は記憶し、次回以降も使う
  - 未設定のときの初期値は、アプリのフォルダ内の `records/exports/`
  - **フォルダが無いときは自動で作成し、「フォルダが無かったので作成しました：（場所）」と画面に表示する**（設定を保存するとき・出力するときの両方）
  - 作成できない・書き込めないとき（ドライブが無い、ネットワークドライブが切れている、権限が無いなど）は、理由と対処方法を表示し、設定の保存・出力をしない
  - Cドライブ直下（`C:\返品取込` など）も指定できる。ただしPCを使うほかの人からも見えることがあるため、初期値にはしない
  - 販売管理システムが取込ファイルを読みに行く共有フォルダなどを指定する想定
- 出力後、伝票の状態を `出力済み` にし、出力履歴（下記）に追記する

**出力履歴** `records/export_history.csv`（出力先を変えても、履歴は1か所にまとめる）

| 列 | 内容 |
|---|---|
| 出力日時 | `YYYY/MM/DD HH:MM:SS` |
| 取引先コード | |
| 伝票番号 | |
| 明細行数 | |
| 出力ファイル名 | |
| 元PDFファイル名 | |

- C6 の重複チェックは、このファイルを使う
- 出力履歴はアプリを再起動しても残る

### F6. 出力値の決め方
| 状態 | Excelに出す値 |
|---|---|
| 人が正解を入力している | 正解の値（表記ゆれをそろえたもの） |
| 正解が未入力で、F7でOCR結果を採用して確定した | OCRの値（表記ゆれをそろえたもの） |
| どちらでもない | 確定できない（その伝票は `確認中` のまま） |

### F7. 確定操作
確認画面に **「この伝票を確定」ボタン** を追加する。

| 項目 | 内容 |
|---|---|
| 確定の単位 | 伝票（PDF）単位。複数ページの伝票は、全ページを確認してから確定する |
| 確定の条件 | すべての明細の必須項目に値がある（正解の入力、またはOCR結果の採用）。C1・C2・C4・C5 のエラーがない |
| OCR結果の採用 | 欄ごとに「OCR結果を採用」を選べる。まとめて採用する場合は、低信頼度（設定値未満）の欄を除く |
| 確定したとき | 状態を `確定済み` にし、確定日時を記録する |
| 確定の取り消し | `出力済み` になる前なら「確定を取り消す」で `確認中` に戻せる |
| 確定後の修正 | 確定後は入力欄を編集できない。修正するときは取り消してから直す |

## 4. 非機能要件

| 項目 | 内容 |
|---|---|
| 性能 | 20ファイル（各1〜2ページ）を、一般的なノートPCで処理できること。OCR中も画面は操作できること |
| 信頼性 | 処理途中でアプリを閉じても、確認・確定した記録と出力履歴は失われないこと |
| セキュリティ | PDFと記録はPC内にのみ保存し、外部に送信しないこと。ただし取込用Excelは、利用者が設定した出力先（共有フォルダなど）に保存する。出力先のアクセス権の管理は利用者側で行う |
| セキュリティ | このPCのブラウザで開いたアプリの画面からの操作だけを受け付けること（ほかのサイトからの操作＝CSRF、DNSリバインディングを断る） |
| セキュリティ | 伝票の文字が「=」で始まっても、Excelで数式として実行されないこと（数式インジェクション対策） |
| 保守性 | 取込フォーマット・取引先マスタ・許容差は、設定ファイルの変更だけで変えられること。出力先は画面で変えられること |
| テスト | チェック処理（F4）、確定（F7）、Excel出力（F5）は、自動テスト（pytest）で確認できること |

## 5. 対象外（今回はやらない）
- 販売管理システムへの直接の登録（APIなど）。今回はExcel出力まで
- 手書き伝票の読み取り
- 複数人での同時利用

## 7. 要確認事項（取込先の仕様）

以下は取込先の販売管理システムの仕様で決まるため、**利用者・システム担当者に確認してから確定する**。確認するまでは、取込フォーマット定義書の仮の値で進める。

| No | 確認すること | 仮の値 | 影響する箇所 |
|---|---|---|---|
| Q1 | 返品を表す伝票区分の値 | `20` | 取込フォーマット A列 |
| Q2 | 返品の数量・金額は、プラスで入れるか、マイナスで入れるか | プラス（マイナス計上は取込側） | 取込フォーマット 数量・金額 |
| Q3 | 金額の端数処理（四捨五入・切り捨て・切り上げ） | 未定（C3は警告） | C3 |
| Q4 | 値引き行の取り込み方（同じ伝票に含めるか、別の区分にするか） | 明細区分 `2`（値引）として同じ伝票に含める | 取込フォーマット 明細区分 |
| Q5 | 返品理由はコードで入れるか、文字で入れるか。コードならその一覧 | 文字（40文字まで） | 取込フォーマット 返品理由 |
| Q6 | 良品/不良区分の値 | `1`：良品、`2`：不良 | 取込フォーマット 良品不良区分 |
| Q7 | 取込ファイルの形式（xlsx / CSV）と、CSVの場合の文字コード（Shift_JIS / UTF-8） | xlsx | 取込フォーマット全体 |
| Q8 | 取引先コードの桁数 | 6桁 | 取込フォーマット D列、取引先マスタ |
