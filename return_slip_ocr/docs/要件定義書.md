## 1. 背景と目的

### 1.1 現状の業務
営業事務の担当者は、取引先から届いた返品伝票（紙・PDF）を1枚ずつ目で見て、次の作業をしている。

1. 返品伝票を受け取る
2. 会社・伝票番号・品番・枝番・数量・単価・**返品理由**を確認する
3. **元の売上**（いつ・いくらで売ったか）を探して、単価や数量が合っているか確かめる
4. 返品理由と現物の状態から、**良品（在庫に戻す）か不良品（廃棄・メーカー返品）か**を判断する
5. 商品名・消費税を調べて、返品計上の資料を作り、販売管理システムに入力する

### 1.2 課題
- 伝票の枚数が多いと、確認・入力に**何時間もかかる**
- 元の売上を探す・消費税を計算する作業が手作業で、間違いが起きやすい
- 金額を間違えると、請求額までずれる

### 1.3 目的
返品伝票PDFをまとめて読み取り、**伝票ごとに変わる値だけをOCRで読み**、それ以外（会社の正式名称・商品名・税率・元の売上）は**マスタと売上データから自動で引いて照合**する。
人が確認・確定した結果から、**返品計上Excel**（罫線つき・税率ごとの消費税・合計）を出力する。

## 2. 方針

| 方針 | 理由 |
|---|---|
| **人の確認を必ず通す** | OCRは間違えることがある。人が確定していないデータは出力しない |
| **OCRで読むのは最小限** | 読む項目が少ないほど、読み間違いと確認の手間が減る |
| **マスタ・売上は照合に使い、上書きしない** | OCRの値とマスタ・売上の値が違っても、黙って置き換えない。警告を出し、人が決める（伝票のほうが正しいこともある） |
| **推測で埋めない** | 読めなかった項目や、判断が必要な項目（良品/不良、売上の候補が複数あるとき）は人が決める |
| **1件の失敗で全体を止めない** | 複数PDFのうち1つが壊れていても、ほかは処理を続ける |
| **データを外に出さない** | OCRもデータベースもPC内だけで動かす。口座など返品計上に使わない大事な情報は持たない |

## 3. 機能要件

### F1. 伝票PDFの読み込み（ドラッグ＆ドロップ・複数ファイル）
- PDFを画面に**ドラッグ＆ドロップ**するか、「ファイルを選択」で選ぶ
- **複数のファイル**を一度に読み込める。1ファイルに**複数ページ**あってもよい
- 上限：1回20ファイル、1ファイル20MBまで
- 読み込めないPDF（破損・暗号化・PDF以外）は、**そのファイルだけエラー**として一覧に出し、ほかは続ける
- 同じPDFをもう一度読み込んだときは、前回の作業記録から続ける

### F2. 伝票一覧
- 読み込んだPDFを一覧で表示し、状態を表示する：`未OCR` / `確認中` / `確定済み` / `出力済み` / `エラー`
- 伝票ごとに**計上月**と**締め日までの残り日数**を表示する。返品処理は締め日までに終わらせる必要があるため（Q10）、締め日が近い伝票（3日以内）は黄色、過ぎた伝票は赤で目立たせ、締め日が近い順に並べ替えられる
- 一覧から選ぶと、その伝票の確認画面を開く
- 「未OCRをすべてOCR」で、まとめて読み取れる（途中で中止できる）

### F3. OCRで読む項目
**伝票ごとに変わる値だけ**を読む。読めなかった項目は空欄にし、人が入力する。

| 区分 | 項目 | 必須 | 読み取り方 | マスタ・売上との照合（F9） |
|---|---|---|---|---|
| 伝票 | 会社名 | ○ | 「御中」の前、または「取引先」の右 | 取引先マスタ（正式名称・別名） |
| 伝票 | 会社コード | △ | 「取引先コード」「得意先コード」の右 | 取引先マスタ。**書いていない伝票もある** → 会社名から引く |
| 伝票 | 伝票番号 | ○ | 「伝票番号」「伝票No」の右 | 出力済みとの重複 |
| 伝票 | 返品日 | ○ | 「返品日」「日付」の右。日付の形にそろえる | 売上日より後か |
| 伝票 | 元売上番号 | △ | 「元伝票番号」「納品書No」の右。**書いていない伝票もある** | 売上データ |
| 明細 | 明細区分 | ○ | 品番が空で、品名欄に「値引」「割引」とある行は `値引` の候補として表示する。**決めるのは人** | − |
| 明細 | 品番 | ○※ | 明細表の「品番」列 | 商品マスタ・売上明細 |
| 明細 | 枝番 | | 明細表の「枝番」列 | 商品マスタ・売上明細 |
| 明細 | 数量 | ○※ | 明細表の「数量」列 | 返品できる残り |
| 明細 | 単価（税込） | ○ | 明細表の「単価」列。値引の行は値引額（マイナス） | 売上単価 |
| 明細 | 返品理由 | ○ | 明細表の「返品理由」列。伝票に1つだけなら全明細に同じ値。読んだ文字を**返品理由マスタ**と照らし合わせてコードにする。見つからなければ選択肢から人が選ぶ | 返品理由マスタ |
| 明細 | 良品/不良 | ○※ | **読み取らず、人が選ぶ** | − |
| 明細 | 税率 | 値引のみ | 値引の行は、人が `10%` / `8%` / `按分` から選ぶ（通常の行は商品マスタから引く。Q15） | − |

△：伝票に書いてあれば読む。なくてもよい（ほかの項目から引く）
※：明細区分が `通常` の行だけ必須。`値引` の行は、数量1・単価＝値引額として扱う（Q11）

**金額・商品名・税率・消費税は読まない。** 数量×単価とマスタから計算する（伝票の金額欄は読まないので、読み間違いの影響を受けない）。

#### F3.1 読み取りの工夫と効果（Issue #19）

「精度が上がった」を数字で言えるように、先に**測る道具**を作ってから直した（`tools/ocr_benchmark.py`）。
正解つきの架空伝票を自動で作り（きれいなPDF／スキャン風／小さい文字 × 10枚）、アプリと同じ流れで読んで正解率を出す。
結果は `docs/test_reports/OCR精度_*.md` に残す。

| 工夫 | 何をするか | どこ |
|---|---|---|
| ① 罫線で列を決める | 画像から明細表の縦線を見つけ、列の境界にする。右寄せの数字が隣の列に混ざらない | `services/table_lines.py` |
| ② 見出しの読み違いを並びで補う | 「数量」を「ブ#」と読んでも、見出しの並び（品名と単価の間）から数量とみなす。数が合わないときは推測しない | `services/table_mapper.py` |
| ③ 欄ごとに文字を絞って読み直す | 欄を切り出し・拡大し、列に出る文字だけ（数量は数字、品番は英数字とハイフン）で読み直す。空欄は読まない | `services/ocr_refine.py` |
| ④ 見出しの値も読み直す | 伝票番号・返品日・会社コードなど。見出しと値が1つの枠のときは空白で切って値だけ読む | `services/ocr_refine.py` |
| ⑤ マスタの値で直す | 取り違えやすい文字（O/0・I/1・S/5）の入れ替え、または1文字違いで、マスタの値が**1つだけ**当てはまるときだけ直す | `services/candidates.py` |

**効果**（同じ30枚、表記ゆれは正解に数える）

| 項目 | 直す前 | 直した後 |
|---|---|---|
| 品番 | 53.5% | 100% |
| 枝番 | 78.1% | 98.2% |
| 数量 | 27.2% | 95.6% |
| 単価 | 7.0% | 100% |
| 返品理由 | 64.9% | 93.9% |
| 見出し（会社名・会社コード・伝票番号・返品日） | 76.7〜100% | 100% |
| 元売上番号 | 66.7% | 83.3% |
| **全項目** | **54.2%** | **97.4%** |

残る間違いはスキャン風の伝票に集まっている（返品理由の2文字以上の読み違い、元売上番号の S→5 など）。
これらは要確認として人が直す。アプリではマスタ・売上データ（⑤）が使えるので、元売上番号はさらに改善する見込み。

> **人が判断する点**：⑤は「読んだ文字を書き換える」機能なので、直しすぎると本当に別の品番だった場合に気づけない。
> そのため、1文字違いの品番（FILE-0551 と FILE-0552）は直さず、取り違えやすい文字の入れ替えだけに限っている。

### F4. 入力チェック
確定（F7）と出力（F5）の前にチェックする。

| No | チェック内容 | 種類 |
|---|---|---|
| C1 | 必須項目（会社名・伝票番号・返品日・明細区分・単価・返品理由。通常の行は品番・数量・良品/不良も）が入っている | エラー |
| C2 | 数量・単価が数値である。通常の行は数量が1以上の整数・単価が0より大きい。値引の行は単価がマイナス | エラー |
| C3 | 返品理由が返品理由マスタのコードに決まっている | エラー |
| C4 | 返品日が日付として正しい | エラー |
| C6 | 同じ「会社コード＋伝票番号」が、すでに確定・出力されている | 警告 |

※ 1.2版の C3（数量×単価＝金額）は、金額を読まなくなったため廃止し、番号を返品理由のチェックに使った。C5（取引先）は F9 の S1 に移した。

### F5. 基幹システム取込用Excelの出力
- 伝票一覧の「**確定済みを取込用Excelに出力**」ボタンで、`確定済み` でエラーのない伝票をまとめて1つのExcelに出力する
- 書式は [取込フォーマット定義書](取込フォーマット定義書.md) **2.0版** に従う（列の順番・列名・コード値は `import_format.json` で変えられる）
- 実務では、このExcelを基幹システムの取込機能でインポートする（1日50枚分をまとめて）
- 人が読む資料としての [返品計上Excel定義書](返品計上Excel定義書.md)（伝票別シート・税率ごとの消費税）は、優先度を下げて後回しにする。消費税の計算式は画面の「合計と照合」に表示する
- **消費税は自動で計算する**（Q9：単価は税込）
  - 伝票ごと・税率ごとに、税込金額を合計する（値引の行も含める）
  - うち消費税 ＝ 税込合計 × 税率 ÷（100 ＋ 税率）を、**税率ごとに1回だけ**、取引先マスタの端数処理で丸める（明細1行ずつ計算して足さない）
  - 税抜金額 ＝ 税込合計 − うち消費税
- **値引の税率が `按分` のとき**（Q15）：同じ伝票の通常の行の、税率ごとの税込合計の比率で値引額を分ける
  - 例：10%対象 1,000円・8%対象 500円、値引 −150円 → 10%に −100円、8%に −50円
  - 割り切れない端数（1円未満）は、税込合計が大きいほうの税率に寄せる（分けた合計が必ず元の値引額と同じになるように）
  - 通常の行が1つの税率だけのときは、按分を選んでもその税率に全額入れる
  - 分けた結果は、Excelの一覧に税率ごとの2行として出し、「按分」と表示する
- 出力しなかった伝票とその理由、警告がある伝票を画面に表示する
- 出力先は利用者が画面で設定する（1.2版のとおり。フォルダが無ければ作成してお知らせする）
- 出力後、伝票の状態を `出力済み` にし、返品記録（データ設計書 t_return_slip）に出力日時を残す

### F6. 出す値の決め方
| 状態 | 使う値 |
|---|---|
| 人が正解を入力している | 正解の値（表記ゆれをそろえたもの） |
| 正解が未入力で、OCR結果を採用した | OCRの値（表記ゆれをそろえたもの） |
| どちらでもない | 確定できない |

### F7. 確定操作
1.2版のとおり（伝票単位で確定・取り消し。出力済みは取り消せない）。加えて：
- 確定すると、返品記録（t_return_slip・t_return_line）に登録し、**返品できる残り**の計算に入れる
- 取り消すと、返品記録から外す

### F8. マスタ・売上データの取り込み
- 取引先マスタ・商品マスタ・売上データを、**Excel / CSV** からデータベース（SQLite）に取り込む
- 取り込む前に全行をチェックし、**1行でもエラーがあれば取り込まない**。何行目の、どの列が、なぜダメかを一覧で表示する
- 取り込み用Excelの**見本**（列名だけ入ったファイル）を画面からダウンロードできる
- 詳細は [データ設計書](データ設計書.md) 4章

### F9. マスタ・売上との照合
**会社の特定**

| No | 内容 | 種類 |
|---|---|---|
| S1 | 会社コード（無ければ会社名・別名）が取引先マスタにある | エラー |
| S2 | 会社コードと会社名の両方が読めたとき、マスタ上で同じ会社を指している | エラー |

**元の売上の特定（明細ごと）**

| 伝票の状態 | 探し方 |
|---|---|
| 元売上番号が**書いてある** | その売上番号の明細から、品番・枝番が同じ行を探す |
| 元売上番号が**書いていない** | 同じ会社・品番・枝番で、返品日以前の売上から、**返品できる残りがある**ものを新しい順に探す |
| 候補が**1件** | その売上を照合先として表示する（人が確認して確定） |
| 候補が**複数** | 候補の一覧（売上日・売上番号・単価・残り）を出し、**人が選ぶ** |
| 候補が**0件** | エラー S3 |

| No | 内容 | 種類 |
|---|---|---|
| S3 | 元の売上が見つかる | エラー |
| S4 | 品番・枝番が商品マスタにある | エラー |
| S5 | 返品数量が「返品できる残り」以下である | エラー |
| S6 | 単価が、元の売上の単価と同じ | **警告**（伝票の単価で計上する。差異をExcelに出す） |
| S7 | 返品日が、元の売上日より後 | 警告 |
| S8 | 確定する日が、返品日の締め日を過ぎていない | 警告。過ぎているときは**次の締め期間に計上**する（翌月の請求で相殺。Q14）。「締め日（11/20）を過ぎたため、12月計上にしました」と画面とExcelに表示する |

- **値引の行**は、元の売上との照合（S3〜S7）をしない

**計上月の決め方**（Q10）：返品日が、取引先の締日で区切った期間のどこに入るかで決める。
例：締日20日の取引先で、返品日11/15 → 11月計上（締め日11/20）、返品日11/25 → 12月計上（締め日12/20）。締日が末日（99）なら返品日の月。
**締め日を過ぎて確定したとき**（Q14）：確定した日が入る締め期間の計上月にする。例：返品日11/15・確定日11/22（締め日11/20を過ぎた）→ **12月計上**（12月の請求で相殺）。

## 4. 非機能要件

| 項目 | 内容 |
|---|---|
| 性能 | 20ファイル（各1〜2ページ）を、一般的なノートPCで処理できること。OCR中も画面は操作できること |
| 信頼性 | 処理途中でアプリを閉じても、確定した記録・出力の記録は失われないこと。マスタの取り込みは全部成功するか、何も変えないかのどちらか |
| セキュリティ | PDF・記録・データベースはPC内にのみ保存し、外部に送信しないこと。返品計上Excelは利用者が設定した出力先に保存する。口座番号などは持たない |
| セキュリティ | このPCのブラウザで開いたアプリの画面からの操作だけを受け付けること（CSRF・DNSリバインディング対策） |
| セキュリティ | 伝票やマスタの文字が「=」で始まっても、Excelで数式として実行されないこと |
| 使いやすさ | ドラッグ＆ドロップで読み込める。エラーには「原因」と「対処方法」を表示する |
| 保守性 | Excelの書式・端数処理などは設定またはマスタで変えられること |
| テスト | チェック（F4・F9）、確定（F7）、取り込み（F8）、出力（F5）は自動テスト（pytest）で確認できること |

## 5. 対象外（今回はやらない）
- 販売管理システムへの直接の登録（APIなど）。今回はExcel出力まで
- 在庫数の管理（良品/不良は記録してExcelに出すが、在庫の増減はしない）
- 手書き伝票の読み取り
- 複数人での同時利用
